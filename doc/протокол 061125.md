## Принятые технические решения

Для задания конфигурации генерации трафика (send) временно используется генерация кода и перекомпиляция при изменении конфигурации:

- разбор JSON и динамическая конфигурирование и загрузка данных отложены из-за неожиданной сложности обработки
- реализован транслятор JSON-конфигурации в .cpp/.hpp код: `src/json2cpp.py`
	- файл конфигурации `etc/config.json`
	- транслируется в `tmp/config.json.hpp` + `tmp/config.json.cpp`

### `tmp/config.json.hpp`

- прописываются все имена и ссылки для объектов из JSON-конфигурации,
- в том числе указатели на прекомпилированные бинарные данные с датчиков
```cpp
#pragma once
#include "types.hpp"
extern CONFIG config;
extern GROUP g1d;
extern SENSOR sensName1;
extern uint8_t _binary_data_PLT4600_gen_1_S_1_1_gen_start;
extern uint8_t _binary_data_PLT4600_gen_1_S_1_1_gen_end;
extern SENSOR sensName2;

extern uint8_t _binary_data_PLT4600_gen_1_S_1_2_gen_end;

```

### `tmp/config.json.cpp`
```cpp
#include "config.json.hpp"

CONFIG config = {
    .baseCPUIndex = 0,
    .groups = {
        &g1d,
        &g2d,
    },
    .sensors = {
        &sensName1,
        &sensName2,
        &sensName3,
    },
};

GROUP g1d = {
    .name = "g1d",
    .duration = 60,
    .loop = false,
    .freq = 1000,
    .packetSize = 18496,
    .sensors = {
        &sensName1,
        &sensName2,
    },
};

SENSOR sensName1 = {
    .name = "sensName1",
    .src = {pcpp::IPv4Address("10.110.100.1"),40000},
    .dst = {pcpp::IPv4Address("10.120.101.11"),50000},
    .sn = 2531001,
    .dataPath = "./data/PLT4600_gen_1/S_1_1.gen",
    .start = &_binary_data_PLT4600_gen_1_S_1_1_gen_start,
    .end = &_binary_data_PLT4600_gen_1_S_1_1_gen_end,
    .size = 1868096,
    .packetSize = 18496,
    .packets = 101,
};
```

- .gen файлы с данными прекомпилируются в исполняемый файл через конвертацию файлов данных в объектные файлы:
	- `objcopy -I binary -O elf64-x86-64 -B i386 data/PLT4600_gen_1/%.gen tmp/%.gen.o`

## План работ

- реализация связки из двух компонентов
	- слайсер
		- нарезка исходного .gen файла
		- обновление счётчиков времени/пакетов
		- нарезка на UDP/Ethernet фреймы
	- сендер
		- отправка в DPDK/SendPackets
		- планирование точного времени отправки каждой группы пакетов
	- связка реализуется через кольцевой буфер
		- слайсер работает несинхронно до тех пор пока есть свободное время в кольцевом буфере
		- останавливается если кончилось место
		- или сендер выставил mutex приостановки добавления новых данных (на период работы SendPackets)
